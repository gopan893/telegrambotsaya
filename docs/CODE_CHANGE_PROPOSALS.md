# Code Change Proposals

## Overview

Code change proposals are generated by the Coding Workspace to plan and document code changes before any implementation. They are **plans only** — no code is mutated.

## Proposal Flow

```
1. User sends coding request
2. Classifier detects category and risk level
3. Repo context is loaded
4. Change plan is generated
5. Risk review runs (5 agents)
6. Test plan is generated
7. Codex prompt is generated
8. If GitHub proposal requested:
   a. Evaluation v2 gate runs
   b. Proposal is created (not written to GitHub)
   c. Executor approval required
```

## Change Plan Structure

```json
{
  "id": "plan_xxx",
  "workspaceId": "ws_xxx",
  "userId": "user1",
  "category": "bug_fix",
  "title": "Fix login bug",
  "requestSummary": "User cannot login",
  "affectedAreas": ["src/bot", "src/core"],
  "proposedFiles": ["src/bot/auth.js"],
  "implementationSteps": ["..."],
  "compatibilityChecklist": ["..."],
  "riskLevel": "low",
  "requiresApproval": false,
  "status": "planned",
  "constraints": { "..." },
  "createdAt": "...",
  "updatedAt": "..."
}
```

## Risk Review

Each plan is reviewed by 5 agents:

1. **Coder** — Can this be implemented?
2. **Planner** — Does it fit the roadmap?
3. **Critic** — What could regress?
4. **Security** — Any security risks?
5. **Executor** — Does it need approval?

## GitHub Proposals

GitHub issue/PR proposals are **never written directly**. They go through:

1. Evaluation v2 gate (must pass)
2. Proposal creation (stored locally)
3. Executor approval required
4. Only then can external write proceed

This ensures no accidental GitHub writes.
